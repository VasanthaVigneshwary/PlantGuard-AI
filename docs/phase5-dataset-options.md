# Phase 5 — Dataset options and recommendation

Research date: 2026-10-28. No dataset was downloaded; no model was trained, no package was installed, and no existing report or source file was changed.

## Recommendation

**Primary strategy: build a small, consented Plant Guard field collection with clear project rights and expert-reviewed labels.** There is no verified public dataset that simultaneously covers the app's full 14-crop taxonomy, supplies both healthy and diseased examples for every crop, reflects field conditions, and grants unambiguous rights to train and redistribute a resulting model. A project collection can make the desired crop coverage and rights explicit. Agree the image-use release before collection: permission should cover storing images, research/model training, publishing aggregate metrics, and whether model weights and any sample images may be redistributed. Record a source ID, licence/release, attribution, label source/reviewer, plant/capture group and duplicate group in each intake CSV row. Avoid person names and precise farm coordinates.

**Fallback: an Apple-only pilot using Plant Pathology 2020 FGVC7**, after accepting and reviewing Kaggle's terms. It has expert-annotated apple healthy, scab, cedar rust and complex-disease labels in field-like orchard photos, and overlaps three model outputs. It cannot support a multi-crop claim. Do not publish its images; Kaggle's terms prohibit redistribution of competition data, and the status of redistributing a model trained on it needs a separate terms review. A fully redistributable fallback is to collect a small, permissioned apple set rather than assume that a dataset licence grants rights to model derivatives.

Use PlantDoc as disease-side field context only; it has no explicitly healthy labels. Use PlantVillage only for controlled-domain development, not as an independent test for the current model. PlantWild and PlantSeg are potentially useful research/benchmark sources, but their licences, per-image provenance or health-label semantics make them unsuitable as the default source for a redistributable competition model without written rights review.

This is a staged scope, not an accuracy claim. Start with any crops for which both statuses and compatible disease labels are explicitly established. Do not include an incomplete crop in a comparison as if the 38-class model supports both outcomes.

### Licence interpretation for training and redistribution

“Open” or “public download” does not automatically mean unrestricted model-weight redistribution. The clearest source declarations here are CC BY 4.0 (attribution required), CC BY-SA 3.0 (attribution and ShareAlike obligations), CC BY-NC 4.0 (non-commercial use), and CC BY-NC-ND 4.0 (non-commercial, no shared derivatives). Kaggle adds separate competition terms including data non-redistribution. The rights holder of each image may differ from the platform account that hosts the archive. Before using any such set for a publicly distributed model, retain the exact licence text/version, source attribution, file-level licence metadata if supplied, and written clarification for any ambiguity about model weights. The recommendation avoids relying on unclear derivative rights by collecting images under a project-specific release.

## Intake CSV and leakage handling

The CSV template is [`dataset-manifest-template.csv`](dataset-manifest-template.csv); field rules and validator usage are in [`dataset-intake.md`](dataset-intake.md). Populate one row per **original** photo. Record source dataset/version, exact source URL or ID, exact licence and attribution, capture category, reviewer, review status, and any known plant/session/source-image/augmentation group. Preserve source labels separately; map to a model class only when the disease and crop are explicit and confirmed. Generic “leaf” labels remain unknown. Keep every augmented derivative in its original-image group and never place relatives across splits.

The intake validator now treats `health_status` independently from optional `disease_label`. Confirmed diseased records can omit exact identity or retain a source-confirmed identity outside the model taxonomy; these records remain eligible for binary health-status evaluation, while unsupported exact identities are warned and excluded from 38-class exact-disease counts. The `crop` field must still match a crop supported by the current model.

Deduplicate by exact file SHA-256 first. Then group by plant, capture session, original image/source URL, and augmentation ancestry. Review perceptual-hash candidates and visually similar web images; the validator does not provide near-duplicate detection. Split groups into train, validation, locked final test, and an external field set. Never tune thresholds, select models or choose rejection rules on the locked test. The current model's PlantVillage exposure means that no PlantVillage record can be presented as an independent test for that model, even if it is held out from a new binary candidate's training.

For candidates with class-level or multi-label conditions, keep source labels intact and map `health_status=diseased` only when the source positively labels disease. For the 2020 “complex disease” class, binary-diseased may be appropriate even when it has no single supported `disease_label`. Do not use uncertain samples as healthy.

The machine has an Intel i5-1334U, integrated Intel UHD graphics, no CUDA GPU; RAM was unavailable in the earlier audit and the active environment lacks PyTorch/TensorFlow. Do not install a framework or start training until this is rechecked. For a few-thousand-image, 224px EfficientNetV2-S fine-tuning experiment, budget **hours per epoch on CPU as a planning risk**, not a measured runtime; an 18k–23k image run may take many hours to multiple days across epochs and repeated settings. Image decoding, disk speed, thermal throttling and RAM can dominate. A future approval should first permit a framework feasibility check and a one-epoch timing pilot on a small development split. Do not train on the locked test. A smaller frozen-feature/binary-head pilot may reduce runtime, but it still needs validation and does not prove field accuracy.

## Model comparison scope once data and rights are cleared

1. A: run the unchanged ONNX 38-class system on the same held-out images, treating its raw score as uncalibrated; measure binary health status only where explicit ground truth and model coverage exist.
2. B: train a separate binary classifier using only reviewed healthy/diseased labels, with per-crop performance and a crop-aware unsupported path.
3. C: evaluate a two-stage candidate only if validation demonstrates benefit. Tune any threshold/reject rule on validation data and report coverage, abstention rate, selective accuracy, precision/recall/F1, confusion matrix, and per-crop metrics.
4. Report controlled and external field metrics separately, with source and crop sample counts, confidence intervals where appropriate, label exclusions, exact/near-duplicate audit status and all licence limitations.

Do not claim 90% based on dataset size, in-domain results, or a handful of examples. No accuracy improvement is established by this source review.
